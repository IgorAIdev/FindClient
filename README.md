# FindClient

Первая рабочая версия сборщика публичных контактов компаний для звонков и переписки.
Python 3.10+, SQLite, без внешних Python-зависимостей. Подходит для Ubuntu VPS.

## Быстрый запуск

```bash
git clone https://github.com/IgorAIdev/FindClient.git
cd FindClient
python3 findclient.py import seeds.json
python3 findclient.py crawl --limit 7
python3 findclient.py list
python3 findclient.py export contacts.csv
python3 findclient.py report report.html
```

Открыть report.html в браузере, CSV — в Excel/LibreOffice. Это статический отчёт,
не веб-сервер. База сохраняется в data/findclient.sqlite3. Для другого пути указать
`--db /путь/база.sqlite3` перед командой.

## Поиск новых компаний

В campaign.json задаются поисковые запросы и название кампании. Используется
[Brave Search API](https://api-dashboard.search.brave.com/documentation/guides/authentication).
Ключ задаётся переменной окружения BRAVE_SEARCH_API_KEY на сервере; не записывать его
в GitHub. API может требовать оплаты по условиям выбранного плана.

```bash
python3 findclient.py search campaign.json
python3 findclient.py crawl --limit 20
```

По 20 результатов на запрос. Поисковая выдача содержит кандидатов, в том числе
каталоги и продавцов: она не доказывает, что компания является производителем.
До ручной проверки у всех роль unverified. Стартовые семь сайтов найдены
6 октября 2026; наличие небольшого заказа и интерес к бартеру не проверены.

## Prom.ua: компании и есть ли у них сайт

Продавцы с prom.ua собираются из страниц категорий или профилей. Берутся только
публичные данные самой страницы: название, город, телефон и email из разметки
schema.org, адрес сайта из поля профиля. Профиль без своего сайта, с магазином на
`*.prom.ua`, соцсетью или бесплатным конструктором получает пометку «слабый сайт» —
это кандидаты на бартер «материалы за сайт».

```bash
python3 findclient.py prom --config campaign.json --limit 20   # категории из prom_pages
python3 findclient.py prom https://prom.ua/c3777612-tentkiev-proizvodim-remontiruem.html
python3 findclient.py audit --limit 30
python3 findclient.py report report.html
```

Скачиваются только страницы без параметров в адресе (`/<категория>.html` и
`/c<id>-<имя>.html`), пауза 2 секунды; ссылки с `?`, поиск и страницы контактов prom.ua
не открываются. Телефон со страницы профиля берётся из публичной разметки, но не
проверяется дозвоном.

Команда `audit` проверяет только главную страницу и sitemap.xml каждого собственного
сайта (с учётом robots.txt) и сохраняет оценку 0–100 по HTML: HTTPS, мобильная
версия, title/description, заголовки, объём текста, alt у картинок, schema.org,
sitemap, блог, год в подвале, скорость, устаревшая вёрстка. Главная страница запрашивается дважды: как обычным клиентом и как телефоном (User-Agent с пометкой FindClient). Мобильная адаптация (`viewport`) оценивается по ответу для телефона, а в деталях отмечается, отдаёт ли сайт отдельную мобильную версию по типу устройства (так делают сайты на конструкторе prom.ua: в режиме «версия для ПК» на телефоне открывается десктопная). Предложение выбирается так:

| Предложение | Когда |
|---|---|
| `site` | своего сайта нет — сайт-визитка/каталог |
| `prom_site` | сайт собран на конструкторе prom.ua с собственным доменом — SEO-статьи/блог или отдельный сайт |
| `redesign` | оценка ниже 45 — переделка или адаптация |
| `seo` | 45–74 — техническая оптимизация и статьи |
| `content` | от 75, но нет блога или в sitemap меньше 15 страниц — SEO-статьи |
| `none` | сайт в хорошем состоянии |
| `unreachable` | сайт не открылся автоматически — проверить вручную |

Оценка — грубая эвристика по HTML одной страницы, не замена Lighthouse и ручного
просмотра. Скорость измеряется с вашего сервера. Сайты на конструкторах часто получают
высокий балл по технике, но без блога — для них будет `content`.

### Видимость в поиске

Техническая оценка не говорит, находят ли сайт. Команда `seo` проверяет через Brave Search
API (нужен `BRAVE_SEARCH_API_KEY`), на каком месте домен компании в топ-20 по запросам
из `seo_queries` в campaign.json. Каждый запрос проверяется как есть и с городом
компании; запрос `site:домен` показывает, есть ли сайт в выдаче вообще (`0`, `1-19`, `20+`:
Brave не отдаёт общее число страниц). Видимость 0–100: топ-3 — 1 балл, топ-10 — 0,6,
топ-20 — 0,3, не найден — 0, среднее по запросам. Результаты запросов кэшируются в
рамках запуска, между запросами пауза 1 секунда.

```bash
python3 findclient.py keywords          # слова из объявлений продавцов prom.ua (подсказка для seo_queries)
python3 findclient.py seo campaign.json --limit 20
python3 findclient.py report report.html
```

Ключевые слова вы задаёте сами в `seo_queries`. Команда `keywords` показывает, какие фразы
повторяются в названиях товаров у нескольких продавцов prom.ua, это формулировки рынка, но
не частота поисковых запросов: объёмов запросов здесь нет. Это поиск Brave, а не Google,
поэтому позиции годятся для сравнения компаний между собой, но не равны позициям в Google.

## Работа с контактами

```bash
python3 findclient.py update 1 --status called --notes "Перезвонить в пятницу"
python3 findclient.py update 1 --role manufacturer
python3 findclient.py update 2 --status do_not_contact
```

Статусы: new, called, written, replied, interested, closed, do_not_contact.
Роли: manufacturer, seller, installer, directory, unverified.
Повторный импорт не стирает статус и заметки. Совпадающие домены объединяются;
в текущей версии один домен = одна компания, первый campaign сохраняется.
Источники обнаружения записываются отдельно. На площадках с множеством компаний
на одном домене потребуется отдельный адаптер — их лучше пока проверять вручную.

Каждый контакт хранит URL источника и дату извлечения. Старые контакты сохраняются
с прежней датой, даже если исчезли с сайта. Дата извлечения не означает проверку
дозвоном или доставкой письма. Производитель не определяется автоматически.

## Автодеплой на VPS через GitHub

Тесты запускаются на каждый push и pull request. После слияния в `main` workflow
`.github/workflows/deploy.yml` заходит на сервер по SSH и запускает `deploy/install.sh`:
клонирует или обновляет код в `~/FindClient`, создаёт `data/` и `.env`, гоняет тесты. Папка `data/`
(база) и `.env` (ключ) не перезаписываются. Если секреты ниже не заданы, деплой пропускается.

Один раз на сервере создайте отдельного пользователя и ключ (не root, не пользователь с другими проектами):

```bash
ssh-keygen -t ed25519 -N "" -f deploy_key          # на своём компьютере
# содержимое deploy_key.pub добавить в ~/.ssh/authorized_keys пользователя на VPS
ssh-keyscan -p 22 ВАШ_ХОСТ                          # строки сверить с отпечатком сервера
```

В GitHub, Settings → Secrets and variables → Actions:

| Секрет | Значение |
|---|---|
| `VPS_HOST`, `VPS_USER` | адрес сервера и имя пользователя |
| `VPS_SSH_KEY` | содержимое приватного `deploy_key` |
| `VPS_KNOWN_HOSTS` | вывод `ssh-keyscan` (проверка, что это ваш сервер) |
| `VPS_PORT` | порт SSH, если не 22 |

Переменные (Variables): `VPS_APP_DIR` (абсолютный путь, по умолчанию `~/FindClient`) и
`VPS_INSTALL_CRON=1`, чтобы добавить cron по понедельникам в 08:00 по времени сервера
(`prom`, `audit`, `seo`, `report`). Ключ Brave впишите в `.env` на сервере сами. Ключ SSH и ключ Brave
в репозиторий не попадают. Отчёт `report.html` создаётся на сервере; веб-сервера для него скрипт не ставит.

## Регулярный запуск на Ubuntu

После ручного успешного запуска можно добавить cron (пример для установки в
/opt/FindClient). Ключ хранить в отдельном приватном файле /opt/FindClient/.env
с shell-строкой `export BRAVE_SEARCH_API_KEY=...` и правами chmod 600.

```cron
0 8 * * 1-5 cd /opt/FindClient && . ./.env && /usr/bin/flock -n /tmp/findclient.lock sh -c 'python3 findclient.py search campaign.json && python3 findclient.py crawl --limit 30 && python3 findclient.py report report.html' >> data/run.log 2>&1
```

Перед включением cron создать data (`mkdir -p data`). Расписание использует часовой
пояс сервера. Не запускать сборщики одновременно с одной базой. Само расписание
этим репозиторием не устанавливается. Существующие проекты VPS не меняются.

## Ограничения первой версии

- Собирается обычный HTML и контактные страницы, максимум 4 страницы на компанию.
- robots.txt учитывается; при ошибке его загрузки сайт пропускается, кроме 404.
- Между страницами пауза от 2 секунд. Блокировки и CAPTCHA не обходятся.
- JS-сайты, скрытые контакты, OLX и соцсети требуют отдельных адаптеров; prom.ua поддержан только через профили и категории.
- Телефоны в тексте могут содержать ошибки; перед звонком проверить источник.
- Нет автоматической рассылки; оценка сайта — грубая, по главной странице.
- Публичный код не содержит рабочей базы, секретов и заметок.
- Для недоверенных источников запускать в изолированном процессе с запретом доступа
  к внутренней сети на уровне firewall; DNS-проверка в коде не заменяет этот запрет.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Проверяются извлечение контактов, сохранность статусов, дедупликация, robots.txt,
экранирование отчёта и защита CSV от формул, разбор профилей prom.ua, оценка сайтов и миграция старой базы. Онлайн-поиск требует действующего ключа.
